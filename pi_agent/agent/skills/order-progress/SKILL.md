# 订单进度查询规范

## 适用场景
- 用户给出订单号，询问订单状态、当前工序、负责人、计划完成日期、工序流转等
- 用户按**技术员**问单：「XXX 目前的订单情况」
- 用户按**业务类型/基地/时间段**问单：「广州小试这一个月的订单情况」「工艺实验这个月的订单」

## 数据来源
订单进度来自 SQL Server 真实数据（非 mock）。

**数据窗口：仅包含最近 3 个月内有工序活动的订单**（服务端硬限制，点查与列表查询均生效）。查不到订单时，除了提示核对单号/业务范围，还要如实说明系统仅覆盖最近 3 个月，不要断定订单不存在；用户明确要查更早时段的数据时，直接说明超出数据窗口。

**未排产订单：订单需通过 PLM 和 OA 的流程审批后才会流转进 MYEXCEL 进行排产**。排产前订单只登记在登记表里，主表查不到——工具已自动降级查询登记表，命中时返回 `status:"待排产"`，含 `records[]`（每条：`source` 登记表类型、`order_no`、`technician`、`grade`、`base` 地域、`registered_at` 登记时间）。此时如实告知「订单已登记、尚未排产」，报地域/技术员/牌号/登记时间，并说明登记阶段无法区分工艺实验还是小试。若登记表也无记录，才按第 2 段提示用户核对单号 / 审批流程是否走完。

## 5 个业务范围
- **广州工艺实验**：订单号含 EX，完整工序（开单 / 色粉计量 / 混料 / 挤出 / 注塑色板 / 注塑样条 / 最终班长），含技术员字段
- **广州送样&小订单**：订单号不含 EX，完整工序，含技术员字段
- **上海工艺实验**：订单号以 EX 开头，完整工序；**技术员没有独立字段，记录在「技术配方备注」里**，回答技术员是谁时从备注文本中提取
- **小试（全集团）**：仅订单号含 EX 的订单，无注塑色板，其余工序齐备，跨基地查询，含技术员字段
- **OA辅助单（全集团）**：仅注塑工序（字段较少），跨基地查询，含技术员字段

> 注：中试上海（非 EX 的上海订单）暂未接入，查询时如遇到此类订单请如实告知暂不支持。

## 多料次订单（上海工艺实验）
- 一个订单可能返回**多条记录**，每条是一个**料次**（`order_count` = 料次号，如 1、2、3…），需逐料次呈现状态
- **整单完成判定：以最后一个料次（料次号最大者）为准——最后一次料次的最终班长完成，即代表整单完成**；整单完成时间 = 最后料次的完成时间
- 某个料次完成 ≠ 整单完成；回答时先给整单结论（按上述规则判定），再列各料次状态；如有料次未完成但整单已判定完成，如实列出各料次情况即可
- 料次号可能不连续（如 1、2、3、4、5、6、7、9、10 缺 8），属正常现象，按存在的料次处理

## 小试完成判定
- 小试订单的完成信号是**「注塑完成时间」**（点查字段 `注塑完成时间`，列表 status 已按此计算）：有值即视为已完成
- **最终完成时间 = 注塑完成时间**；小试结果里没有 `final_complete_time` 字段，不要用其他时间判断完成
- 注塑人员看 `注塑人员姓名` 字段

## 工具使用
- **query_order_progress(order_no, base?)**：按**具体订单号**查真实进度
  - `base` 可选。如用户未说明，**优先不传 base**（工具会并行查 5 个业务范围取命中）
  - 用户明确说"广州工艺实验的 XX 订单"时，传 `base="广州工艺实验"` 加速查询
  - 订单号含 EX 时优先怀疑工艺实验类（广州工艺实验 / 上海工艺实验 / 小试）
- **query_orders_list(technician?, base?, business_types?, since?, until?)**：**没有订单号**、按维度批量查单
  - 按技术员：传 `technician`（例："张三目前的订单情况"）
  - 按类型/基地/时间段：传 `business_types` / `base` / `since` / `until`（时间按排产时间过滤）
  - 返回订单摘要列表；需要某订单工序明细时，再用其订单号调 query_order_progress
  - **列表结果恰好只有 1 单时：直接用该订单号再调一次 query_order_progress 补全工序明细（各工序负责人 + 时间、当前进行到哪一步），一次性呈现完整进度，不要让用户再追问一次**；2 单及以上保持摘要列表 + 引导"告知订单号可查工序明细"
- **search_orders**：按关键词搜索（目前走 mock 数据）
- **get_production_stages**：标准工序列表

## 业务类型别名（query_orders_list 的 business_types 可直接传别名）
| 用户说法 | 对应业务类型 |
|----------|--------------|
| 研发实验 | 小试（全集团，可能是广州小试也可能是上海小试等） |
| 工艺实验 | 广州工艺实验 + 上海工艺实验 |
| 注塑单 / 研发辅助单 | OA辅助单 |
| 送样 / 小订单 | 广州送样&小订单 |
| 实验单 / 实验 | 广州工艺实验 + 上海工艺实验 + 小试 + OA辅助单（**研发辅助单也要算进实验单**） |
| 所有单 / 全部 / 下单 | 全部 5 类业务范围（**笼统问"下了多少单"必须含 OA辅助单，不能只算实验单**） |

> 口径要点：用户问「下了多少实验单」或「下了多少单」这类**笼统说法**时，OA辅助单（研发辅助单）必须计入，不能因为"OA"就排除。只有用户明确点到「研发实验/工艺实验/注塑单」等具体类别时，才按该类别的精确含义过滤。

## 问法 → 参数映射示例
| 用户问法 | query_orders_list 参数 |
|----------|------------------------|
| "广州小试这一个月的订单情况" | business_types=["小试"], base="广州", since=今天−30天 |
| "研发实验这个月的订单" | business_types=["研发实验"], since=本月1日, until=今天 |
| "工艺实验这个月的订单" | business_types=["工艺实验"], since=本月1日, until=今天 |
| "XXX 目前的订单情况" | technician="XXX"（可加 since=近30天聚焦近期） |
| "XXX 今天下的单有哪些" | technician="XXX", since=今天, until=今天 |
| "上海的注塑单" | business_types=["注塑单"], base="上海" |
| "牌号 ABC123 目前的进度" | grade="ABC123"（可能命中多个类型的订单，逐个列出；要看工序明细再用订单号点查） |
| "PP 产品线当前的订单情况" | product_line="PP"，回答时用 `by_type` 说明每个业务类型各有多少单，再列订单概况 |

- **所有时间问法一律按「排产时间」过滤**——包括"下的单 / 开的单 / 今天的单 / 这个月的单"等说法，不用开单时间
- "今天" = since=今天, until=今天；"本月" = 本月1日 ~ 今天；"近7天/近30天" = 今天−N天 ~ 今天；日期一律换算成 `YYYY-MM-DD` 传入（当前日期见系统提示）
- `base` 只对全集团类型（小试 / OA辅助单）生效；说"广州工艺实验"时直接传 business_types=["广州工艺实验"]，不用再传 base

## 字段说明（查询结果）
| 字段 | 含义 |
|------|------|
| `order_no` | 订单号 |
| `牌号` | 产品牌号 |
| `产品线` | 产品线 |
| `machine` | 机台 |
| `order_count` | 订单数量 |
| `creator` / `create_order_time` | 开单人员 / 时间 |
| `color_powder_measurer` / `color_powder_measure_time` | 色粉计量人员 / 时间 |
| `mixing_person` / `mixing_time` | 混料人员 / 时间 |
| `extrusion_person` / `extrusion_time` | 挤出人员 / 时间 |
| `injection_color_plate_*` | 注塑色板 |
| `injection_strip_*` | 注塑样条 |
| `*_exception` | 该工序异常说明（非空即有异常） |
| `final_monitor` / `final_complete_time` | 最终班长 / 最终完成时间 |
| `注塑人员姓名` / `注塑完成时间` | 注塑人员 / 注塑完成时间（仅小试；注塑完成即视为最终完成） |
| `scheduling_person` / `scheduling_time` | 排产完成人员 / 时间 |
| `技术员` | 技术员（广州工艺实验 / 广州送样&小订单 / 小试 / OA辅助单） |
| `技术配方备注` | 技术配方备注（上海工艺实验），技术员记录在此备注文本中 |

### 列表查询（query_orders_list）结果字段
| 字段 | 含义 |
|------|------|
| `type` | 命中的业务类型 |
| `order_no` / `base` / `machine` / `order_count` | 单号 / 基地 / 机台 / 数量 |
| `grade` / `product_line` | 产品牌号 / 产品线 |
| `technician` / `tech_remark` | 技术员 / 技术配方备注（上海工艺实验的技术员需从 tech_remark 文本中提取） |
| `status` | `已完成` / `生产中`（上海工艺实验为订单级状态：按最后料次判定） |
| `scheduling_time` / `create_order_time` | 排产时间 / 开单时间 |
| `exceptions` | 异常工序列表（空数组 = 无异常） |
| `lot_total` / `lot_completed` | 料次总数 / 已完成料次数（仅上海工艺实验，一单多料次已聚合到订单级） |

顶层还有 `by_type`（各业务类型的单量统计）——回答"每个类型有多少单"直接用它；
`by_line`（各产品线的单量统计，`product_line` / `total` / `completed`，跨业务类型已合并、不截断）——回答"各产品线分别多少单"直接用 `by_line`，这是真实全量统计，不受明细 200 条限制。

> 未设置的时间字段数据层已统一归一为 `null`（2026-08 起，历史库的 `1900-01-01` / 空串哨兵不再出现），`null` = 未执行/未记录，照实表述即可，不要捏造；
> 点查每行另带 `status`（已完成/生产中）、`current_stage`（当前工序）、`stages[]`（各工序 done 明细），回答"进行到哪一步"直接用 `current_stage`，不需要按工序时间自行推断。

## 回答规范
- **展示订单时，订单号必须同时带上牌号**（点查结果字段名为 `牌号`，列表查询为 `grade`，两者同一含义）。单订单示例：`📦 订单 EX20260804-1042（牌号：PPE-JF206 BK017）`；多订单表格必须包含「牌号」列。牌号为空时省略
- 工具返回的时间**已经是北京时间**（`YYYY-MM-DD HH:mm`），直接照搬展示，不要做任何时区换算
- 人员 + 时间成对呈现，例：`混料：邹华明（2026-06-20 14:30）`
- **某工序有负责人但无完成时间时**，如需人工确认，应联系**该工序的负责人**（如注塑样条未完成 → 联系该订单的注塑样条人员），**不要指向最终班长**（最终班长不负责样条，如广州最终班长是邹华明、注塑样条是杨文超）
- 异常字段非空时用 ⚠️ 标记并展示异常内容
- 已完成工序用 ✅，未完成用 ⏳
- 涉及多订单对比用表格
- 列表查询结果：先给总数概况，**统计一律用 `by_type` 的 `count` / `completed` / `in_progress`（真实总数，不受明细截断影响）**，如"共 N 单：生产中 X / 已完成 Y"；再用表格节选列出部分订单（单号 / 机台 / 牌号 / 技术员 / 状态 / 排产时间 / 异常）。**不要用 `results` 里的行数（rows.length）当统计数**——明细可能只节选最近 200 条（有 `truncated_note` 时如实说明"订单较多，明细仅列最近 200 条，统计数为实际总数"）
- 上海工艺实验行回答技术员时，从 `tech_remark` 文本中提取，不要照搬整段备注
- **回答「各产品线分别多少单」时，必须把 `by_line` 里的每一个产品线都完整列出**（含 1 单的长尾产品线），不得只列前 N 条或把剩余并作「其他/未枚举」省略——用户需要看到全部产品线的精确分布。`by_line` 是全量不截断统计，直接整表呈现即可
- **列表查询结果恰好只有 1 单时**：不要只给摘要——直接用该订单号补一次 `query_order_progress`，把工序节点（各工序负责人 + 完成时间、当前工序 ✅/⏳）一并呈现完整进度；**2 单及以上**才用摘要表格并引导"告知订单号可查工序明细"
