## 一、系统架构

### 1.1 设计模式
- **分层架构**：前端(Next.js) / 服务端(Hono) / Agent 核心(pi_agent) / 数据层(SQL Server)
- **模块化 Monorepo**：`pi_agent`、`server`、`web` 三个 workspace
- **单例连接池**（lazy 初始化）+ **AsyncLocalStorage** 传递用户上下文
- **纯函数数据层**：`sqlServer.ts` 查询/装饰函数无副作用，便于单测与开放接口直连
- **事件驱动**：Agent 底层事件 → 业务事件 → SSE 推送 / 日志落盘

### 1.2 架构图

```
┌──────────────────────────────────────────────────────────────┐
│  前端 web（Next.js）                                          │
│  /chat（SSE 聊天） /dashboard（看板） /bases /capacity        │
└───────────────┬──────────────────────────────────────────────┘
                │ SSE / REST
┌───────────────▼──────────────────────────────────────────────┐
│  服务端 server（Hono, :8001）                                 │
│  /api/chat/:sessionId   /api/sessions/*                       │
│  /v1/*（OpenAI 兼容, MaxKB）  /open/*（开放接口）  /health     │
│  SessionStore（内存）  ExecutionTracer（trace 落盘）           │
└───────────────┬──────────────────────────────────────────────┘
                │ createSession()
┌───────────────▼──────────────────────────────────────────────┐
│  pi_agent（Agent 核心）                                       │
│  7 个领域工具 + 3 个 SKILL + PermissionGuard                   │
│  services/sqlServer.ts（连接池 / 5 套 SQL / 工序装饰）         │
└───────────────┬──────────────────────────────────────────────┘
                │ mssql（只读账号）
┌───────────────▼──────────────────────────────────────────────┐
│  SQL Server（中试生产 ERP，5 个业务范围）                      │
└──────────────────────────────────────────────────────────────┘
                （看板降级）→ PostgreSQL（web/prisma，bases 等 seed 数据）
```

LLM API（百炼/DeepSeek）为外部依赖，agent 通过 `models.json` + `AI_API_KEY` 调用。

## 三、类图关系

```
AgentSession ──调度──▶ 7 个 Tool（defineTool）
     │                    │ execute() 内部
     │                    ├─ checkPermission(tool,args) ──▶ requireCurrentUser()（ALS）
     │                    └─ queryOrderProgress / queryOrdersList / ... ──▶ sqlServer.ts
     │
     ├─ SessionManager（JSONL 持久化 + Compaction）
     ├─ ModelRegistry（models.json）+ AuthStorage（API Key）
     └─ ResourceLoader（注入 AGENTS.md + 3 SKILL.md）

SessionStore（server）──持有──▶ SessionEntry{session, modelChain, dispose}
ExecutionTracer ──订阅──▶ AgentSession events ──▶ record()/finish()

UserContext（ALS）{role, baseId, allowedBusinessTypes}  ──被── permissionGuard / tools 读取
```

## 四、核心流程概要

1. **查单流程**：用户输入 → `/api/chat/:sessionId` → `SessionStore.getOrCreate` → `runPromptWithModelFallback` → LLM 决策调用 `query_order_progress` → 工具查 SQL → 结果 JSON → LLM 格式化 → SSE 流 → 前端渲染。

2. **多维列表流程**：LLM 调用 `query_orders_list` → 别名展开/范围钳制 → 三路并行（明细 + 总数 + 产品线）→ 上海料次聚合 → 结构化统计返回。

3. **MaxKB 多智能体流程**：企业微信机器人 → MaxKB 应用 → `/v1/chat/completions`（带 model）→ `resolveScopeByModel` → 注入 scopeNote + 钳制 businessTypes → 流式返回。

4. **开放接口流程**：外部系统 → `/open/orders/progress`（OPEN_API_KEY）→ 参数校验 → 直连数据层（无 mock）→ 200/404/500 分拣 + 审计落盘。
